# Professional Feature Delivery

## Invoke when

- new feature
- behavior change
- user workflow
- API capability

## Procedure

1. Confirm outcome and acceptance criteria from the user request and repository.
2. Create a task packet and identify affected skills, files, interfaces, data, and risks.
3. Choose the smallest coherent and reversible design.
4. Implement in reviewable increments with tests and observability.
5. Run project-native verification and adverse-condition tests.
6. Update documentation, migration, rollback, support, and evidence.
7. Report only material decisions and blockers to the user.

## Required outputs

- task packet
- acceptance criteria
- implementation
- tests
- evidence record
- progress card

## Completion gates

- [ ] acceptance criteria pass
- [ ] relevant active-skill gates pass
- [ ] no hidden critical findings
- [ ] rollback or recovery is defined

## Operating rules

- Inspect before asking.
- Keep user questions material and minimal.
- Distinguish fact, inference, default, and unresolved uncertainty.
- Use the smallest safe reversible step.
- Record commands and evidence; never fabricate execution.
- Stop before destructive, externally consequential, sensitive, or irreversible action without the required approval.
- Update the shared plan, task packet, decisions, risks, and user-facing progress card.
