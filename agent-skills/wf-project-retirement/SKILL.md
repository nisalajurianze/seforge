# Project Retirement and Decommissioning

## Invoke when

- system retirement
- product shutdown
- legacy replacement
- service decommission

## Procedure

1. Identify users, dependencies, records, data, contracts, assets, and obligations.
2. Create communication and migration plans.
3. Archive or erase data according to retention, legal hold, and privacy rules.
4. Revoke credentials, keys, tokens, certificates, integrations, and remote access.
5. Remove infrastructure, licenses, billing, monitoring, and supplier commitments.
6. Validate closure and retain evidence, lessons, and residual ownership.

## Required outputs

- retirement plan
- dependency closure record
- data disposition evidence
- access revocation evidence
- final acceptance

## Completion gates

- [ ] users and dependencies are handled
- [ ] data obligations are satisfied
- [ ] access is revoked
- [ ] costs and assets are closed
- [ ] evidence is retained

## Operating rules

- Inspect before asking.
- Keep user questions material and minimal.
- Distinguish fact, inference, default, and unresolved uncertainty.
- Use the smallest safe reversible step.
- Record commands and evidence; never fabricate execution.
- Stop before destructive, externally consequential, sensitive, or irreversible action without the required approval.
- Update the shared plan, task packet, decisions, risks, and user-facing progress card.
